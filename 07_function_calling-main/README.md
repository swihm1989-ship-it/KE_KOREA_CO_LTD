# Function Calling 및 오케스트레이션

Python 함수를 도구로 정의하고, 모델의 호출 요청을 실제 실행과 최종 안내로 연결한다. 도구의 입력·반환 검증, 파일·DB·외부 API 연결, MCP를 익히고 도구 선택·조건 분기·병렬 실행·오류 복구로 확장한다.

모델이 요청한 도구와 인자, 프로그램이 실제로 실행한 결과, 최종 답변의 근거를 대조하며 단일 에이전트의 실행 흐름을 이해한다.

## 실습 파일

본인 이름 폴더에서 주제별로 작업한다. 다른 사람의 폴더는 수정하지 않는다.

```text
07_function_calling/
├── README.md
├── .gitignore
├── .env.example
└── 이름폴더/
    ├── .env
    ├── .venv/
    ├── pyproject.toml
    ├── uv.lock
    ├── .python-version
    ├── 01_tool_intro/
    ├── 그 외
```

Python과 uv 환경을 사용한다. 환경과 패키지는 본인 이름 폴더에서 관리하며, 여러 주제가 같은 환경을 사용한다.

주제별 파일과 추가 라이브러리는 해당 수업에서 준비한다. 

강사가 Git에 추가한 자료를 안내된 방법으로 받아 필요한 파일만 본인 폴더로 복사한다. 직접 작성하거나 수정한 파일과 개인 환경은 덮어쓰지 않는다.

## 실습 진행과 실행

편집기의 Python 인터프리터는 본인 이름 폴더의 `.venv`를 선택한다. 실행할 파일의 입력과 설정을 확인한 뒤 Python 실행 버튼으로 실행한다.

모델이나 외부 API를 호출하는 실습과 로컬 도구만 실행하는 실습을 구분한다. 실제 호출 여부와 필요한 설정은 해당 실습의 안내를 따른다.

실행 후에는 모델이 선택한 도구와 인자, 실제 도구 결과, 최종 안내를 차례로 확인한다. 입력이나 조건을 바꾸기 전에 결과를 예상하고, 실행 결과가 예상과 어떻게 다른지 설명한다.


저장 실습은 안내된 사용자 확인 절차를 거쳐 로컬 테스트 자료를 대상으로 진행한다. 조회 결과와 실제 처리 완료를 구분한다.

## 설정과 비밀 정보

레포 루트의 `.env.example`을 복사해 본인 이름 폴더의 `.env`로 저장한다. 제공받은 개인 API 키와 접근 가능한 모델을 설정한다.

03의 웹 검색 예제에는 `TAVILY_API_KEY`도 필요하다. 사용하는 실습에 필요한 키만 추가하고 기존 개인 설정은 유지한다.

LangSmith 실행 추적은 사용하는 실습에서 설정한다. 기본값은 `LANGSMITH_TRACING=false`이며, 추적할 때만 켜고 확인 후 다시 끈다.

API 키는 코드·프롬프트·README에 넣지 않는다. `.env.example`에는 공유할 환경 변수 이름과 비밀 값이 없는 예시만 적는다.

`.env`, `.venv`, 캐시와 `outputs/`·`results/`·`incident-data/`의 생성 기록은 커밋하지 않는다. `pyproject.toml`, `uv.lock`, `.python-version`과 비밀 값이 없는 실습 파일은 함께 커밋한다.

예제에 필요한 CSV·PDF·SQLite 원본 자료는 생성 기록과 구분해 보관한다.

## 실습 기록과 제출

작성한 코드, 변경한 입력과 조건, 관찰 내용을 본인 이름 폴더에 정리한다. 어떤 조건을 바꾸었고 도구 선택·인자·실행 결과·최종 안내가 어떻게 달라졌는지 짧게 설명한다.

관찰 내용을 기록할 때는 API 키와 개인 정보를 포함하지 않는다.

본인 이름 폴더의 변경을 커밋하고 Fork한 레포에서 PR을 보낸다.

## 커밋 메시지 규칙

커밋 메시지는 `유형: 변경한 내용` 형식으로 쓴다. 한 커밋에는 한 가지 작업을 담고, 변경 내용을 짧고 구체적으로 적는다.

- `add`: 코드나 실습 파일 추가
- `fix`: 오류 수정
- `docs`: README나 실습 관찰 기록 등 문서 수정

예시:

```text
add: 사진 인화 견적 도구 연결
fix: 도구 반환값 검증 조건 수정
docs: 주문 조회 조건별 결과 정리
```
