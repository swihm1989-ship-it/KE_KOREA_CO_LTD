# 원하는 도구로 요청에 응답하는 프로그램 만들기

자기 주제의 도구 하나를 정하고, 자연어 요청을 실제 조회·계산과 최종 안내로 연결한다. 주제와 자료는 직접 선택한다. 참고 예제를 읽은 뒤 환경 설정과 모델 호출 뼈대를 활용하고, 자기 문제의 도구·입출력 계약·실행 지시를 작성한다.

## 완성할 흐름

**요청 입력 → 모델의 도구 호출 요청 → 입력 검사 → 실제 실행 → 반환 검사 → 같은 호출 ID로 결과 전달 → 최종 안내**를 완성한다.

- 도구는 실제 자료를 읽거나 계산한다. 모델의 상식만으로 답하지 않도록 연결한다.
- 필수·선택 입력, 기본값의 뜻, 허용 범위와 반환 구조를 직접 정한다. 입력은 `args_schema`, 반환은 Pydantic 모델 생성·검증으로 확인한다.
- 필요한 값이 빠지면 확인 질문을 하고, 정상적인 빈 결과와 실행 실패를 구분한다.
- 한 번 입력하면 한 번 답하는 흐름으로 만든다. 조건 확인 질문을 받으면 필요한 내용을 포함한 전체 요청을 다시 입력한다.

여러 도구의 실행 순서 제어와 사용자 확인 후 저장은 후속 단원에서 확장한다.

## 참고 예제: 예산에 맞는 카페 메뉴 안내

[cafe_menu_example.py](./cafe_menu_example.py)는 `input()`으로 요청을 한 번 받고 [data/menu.csv](./data/menu.csv)의 가상 메뉴 12개를 조회한다. 메뉴 이름·가격·재고·설명을 근거로 답한다.

기존 본인 이름 폴더의 `.venv`와 `.env`를 사용한다. 필요한 패키지는 기존 `langchain-core`, `langchain-openai`, `python-dotenv`, `pydantic`이며, `.env`의 `OPENAI_API_KEY`·`OPENAI_MODEL`을 사용한다. 추가 외부 API 키는 필요 없다.

이 폴더를 통째로 복사하고 편집기의 Python 실행 버튼으로 예제를 실행한다. 입력 안내가 나오면 요청 한 개를 입력한다. 다른 요청을 확인할 때는 다시 실행한다. 예산 누락 시 확인 질문을 출력하고 끝나며 대화 이력을 이어서 저장하지 않는다.

### 예제의 도구와 계약

`lookup_menu`는 최대 예산으로 목록을 조회하며, 종류·온도를 선택 조건으로 받는다.

| 입력 | 규칙 |
| --- | --- |
| `max_price` | 필수. 원 단위 정수이며 0 이상이다. 없으면 예산을 질문한다. |
| `category` | 선택. 전체·커피·차·에이드 중 하나다. 생략하면 모든 종류를 조회한다. |
| `temperature` | 선택. 전체·HOT·ICE 중 하나다. 생략하면 모든 온도를 조회한다. |

`전체`는 선호를 추측한 값이 아니라 해당 조건으로 검색을 제한하지 않는다는 뜻이다. 모델이 선택 인자를 생략해도 함수의 기본값으로 전체를 조회한다. 이 계약은 참고 예제의 설계이며, 자기 주제에서는 필요한 필수·선택 입력을 새로 정한다.

CSV의 `price_won`·`stock`은 정수로 바꾼 뒤 `Menu`로 검사한다. 실제 메뉴 행의 종류는 커피·차·에이드, 온도는 HOT·ICE이며 가격·재고는 0 이상이어야 한다. 모든 행을 검사한 뒤 조건에 맞는 목록을 `MenuResult(menus=...)`로 반환한다.

조회 목록에는 재고 0인 메뉴도 있을 수 있다. 마지막 모델은 이를 추천에서 제외한다. 반환 모델은 `model_dump_json()`으로 바꾸어 원래 호출 ID의 `ToolMessage`에 담는다. 별도의 사람이 작성한 정답 사전을 실행 코드에 넣지 않는다.

### 먼저 확인할 요청

| 요청 | 도구 결과와 최종 안내에서 확인할 것 |
| --- | --- |
| “5천원 이하의 아이스 커피를 추천해 줘.” | 아메리카노 4,000원·재고 12개를 추천한다. 조회된 카페라떼는 재고 0이므로 추천에서 제외한다. |
| “5천원 이하의 아이스 메뉴를 추천해 줘.” | 종류를 추가로 묻지 않고 전체로 조회한다. 재고가 있는 아메리카노·복숭아티·레몬에이드가 추천 가능한 후보가 된다. |
| “아이스 커피를 추천해 줘.” | 예산을 묻고 도구는 실행하지 않는다. |
| “따뜻한 에이드를 7천원 이하에서 추천해 줘.” | `menus=[]`이며 조건에 맞는 메뉴가 없다고 안내한다. |

실행 전 기대하는 인자와 결과를 적고, 실제 호출 인자·도구 결과·최종 답변을 대조한다. 아무 내용 없이 입력하면 모델 호출 없이 입력 안내만 표시한다.

## 개발 요청 프롬프트 예시

다음은 **코드 작성을 돕는 AI에게 전달하는 개발 요청**이다. 목적·자료·도구·계약·예외 상황을 먼저 적는 방식을 참고하고, 자기 주제에 맞게 바꾼다.

```text
예산에 맞는 카페 메뉴를 안내하는 Python 프로그램을 만들어줘.
먼저 도구의 입력·반환 계약을 짧게 설명한 뒤, 독립 실행 파일 한 개로 작성해줘.

자료는 같은 폴더의 data/menu.csv이고 열은 다음과 같아.
menu_id, name, category, temperature, price_won, stock, description
종류는 커피·차·에이드, 실제 메뉴 온도는 HOT·ICE야.

1. 요청은 input()으로 한 번 받는다. 빈 입력이면 안내만 출력하고 끝낸다.
2. 도구는 lookup_menu 하나다. 최대 예산 max_price는 필수 정수이며 0 이상이다.
3. category와 temperature는 선택 조건이고 기본값 전체는 필터를 적용하지 않는다는 뜻이다.
4. 입력·메뉴 행·반환 Pydantic 모델에 ConfigDict(strict=True, extra="forbid")를 적용한다.
   입력 모델은 args_schema로 연결하고, CSV의 가격·재고를 정수로 변환해 행을 검사한다.
5. 실제 CSV를 조회하고 MenuResult의 menus 목록에 검사한 메뉴를 담는다. 빈 목록도 정상이다.
6. LangChain bind_tools로 받은 실제 인자로 도구를 실행하고,
   원래 모델 응답과 같은 call id의 ToolMessage로 검증한 JSON 결과를 전달한다.
7. 마지막 모델은 재고가 있는 메뉴만 가격·재고·자료에 근거한 이유로 안내한다.
8. 예산이 빠졌으면 추측하지 않고 질문한다. 종류·온도 생략은 전체 조회를 허용한다.
9. 자료에 없는 정보나 주문·결제 완료를 만들지 않는다.
10. 모델 설정은 load_dotenv()와 ChatOpenAI(model=os.environ["OPENAI_MODEL"])만 사용한다.
    새로운 공통 모듈이나 실행 옵션은 추가하지 말고 핵심 부분에 짧은 한국어 주석을 달아줘.

정상 요청, 예산 누락, 조회 결과 0건을 확인할 입력도 제시해줘.
```

### 프로그램이 실행할 때의 시스템 지시

개발 요청과 별개로, 프로그램 안의 `system` 지시는 실행 중 모델의 행동을 정한다. 참고 예제는 다음 원칙을 전달한다.

```text
예산이 있으면 도구로 조회하고, 없으면 예산을 질문한다.
종류·온도를 말하지 않으면 전체로 조회한다.
조회한 menus의 재고가 있는 항목만 가격·재고·설명에 근거해 안내한다.
빈 목록이나 전부 품절인 경우에는 추천할 메뉴가 없다고 알린다.
자료에 없는 정보나 주문·결제 완료를 만들지 않는다.
```

실제 코드의 지시에는 지원 범위와 잘못된 조건의 안내도 포함한다. AI가 만든 코드를 받으면 요구한 도구와 계약이 있는지 읽고, 위 요청들을 직접 실행해 확인한다.

## 자기 주제로 바꾸기

먼저 **누구의 어떤 요청을 어떤 자료나 계산으로 해결할지** 한 문장으로 정한다. 필요한 입력, 선택 조건과 기본값, 반환값, 정보가 부족하거나 결과가 없을 때의 답변을 적은 뒤 개발 요청 프롬프트를 작성한다.

| 아이디어 | 도구가 실제로 수행할 일 |
| --- | --- |
| 동아리 장비 안내 | CSV·SQLite에서 용도·예산 등의 조건에 맞는 장비를 조회한다. |
| 시설 이용 안내 | 제공한 PDF에서 질문 주제에 해당하는 페이지의 이용 규정을 읽는다. |
| 행사 준비 수량 계산 | 인원과 준비 기준으로 필요한 물품 수량을 계산한다. |
| 도서 검색 안내 | 선택한 도서 API에서 검색한 제목·저자 등의 정보를 반환한다. |

아이디어는 선택 예시다. 자기 자료와 도구를 정해도 된다. 예제의 안내 문구만 바꾸는 데서 끝내지 않고, 실제 조회·계산과 입출력 계약이 자기 문제에 맞게 동작하도록 만든다.

## 완성 후 남길 것

작성한 코드와 필요한 자료, 다음 세 상황의 기대 결과와 실제 결과를 짧게 정리한다.

1. 정상 요청: 필요한 인자로 도구를 실행하고 실제 결과로 답하는가?
2. 필수 정보 누락: 값을 추측하지 않고 확인 질문을 하는가?
3. 빈 결과 또는 경계 사례: 결과 0건과 잘못된 값·실행 실패를 구분하는가?

도구의 입력·실제 실행·반환 검증과 `ToolMessage` 연결이 코드의 어디에 있는지 설명한다. 계약 검사를 통과했다는 사실과 모델이 원문을 정확히 해석하고 답했다는 판단은 구분한다.

## 나의 과제: NASA 자료로 외계행성 검색하기

우주에 관심 있는 사용자가 원하는 반지름·발견 연도·발견 방법으로 외계행성을 찾고, 실제 NASA 기록의 행성명·항성명·발견 연도·방법·반지름을 안내받는 프로그램이다. 실행 파일은 `exoplanet_search.py`다.

### 실제 자료와 출처

- 제공 기관: NASA Exoplanet Archive / Caltech-IPAC.
- 공식 조회 방법: https://exoplanetarchive.ipac.caltech.edu/docs/TAP/usingTAP.html
- 공식 열·단위 정의: https://exoplanetarchive.ipac.caltech.edu/docs/API_PS_columns.html
- 자료 파일: `data/exoplanets.csv`, 2026-10-27 다운로드, **6,446행**.
- 다운로드 URL·SQL·시각·SHA-256: `data/exoplanets_source.json`.
- NASA 추가 API 키가 필요 없으며 프로그램은 저장한 CSV를 읽는다. 답변 생성에는 기존 OpenAI 설정을 사용한다.

`ps` 테이블에서 `default_flag=1`인 기본 파라미터 기록을 받았다. 반지름이 상한·하한으로만 기록된 행성은 제외하고, 반지름이 비어 있는 행성은 유지했다. 다운로드 SQL은 다음과 같다.

```sql
select pl_name,hostname,discoverymethod,disc_year,pl_rade
from ps
where default_flag=1 and (pl_radelim=0 or pl_rade is null)
order by pl_name
```

CSV 열은 `pl_name`(행성명), `hostname`(항성명), `discoverymethod`(발견 방법), `disc_year`(발견 연도), `pl_rade`(지구 반지름 단위의 반지름)다. 반지름이 없는 1,625건을 0으로 채우지 않으며 크기 검색에서 제외한다. 자료는 내려받은 시점의 검색용 스냅샷이다. 크기가 비슷하다고 지구 같은 환경이나 거주 가능성을 의미하지 않는다.

### 도구의 입력·반환 계약

도구는 `search_exoplanets` 하나다.

| 입력 | 규칙·기본값 |
| --- | --- |
| `max_radius_earth` | 필수. 유한한 양수. 지구 반지름의 몇 배 이하인지 지정한다. 없으면 확인 질문한다. |
| `discovered_since` | 선택. 정수 1900~2026. 해당 연도 포함 이후. 기본값 1900은 이 자료의 전체 연도를 포함한다. |
| `discovery_method` | 선택. 기본값 `전체`는 방법 필터 없음. 그 외 NASA 자료의 11개 발견 방법 중 하나다. |
| `limit` | 선택. 정수 1~10, 기본값 5. 작은 반지름·행성명 순으로 최대 해당 개수만 표시한다. |

통과법은 `Transit`, 시선속도법은 `Radial Velocity`, 직접 촬영은 `Imaging`, 미세중력렌즈법은 `Microlensing`이다. 나머지 허용 방법은 코드의 `DiscoveryMethod`에 적었다. CSV의 발견 방법도 같은 목록으로 검사한다.

반환은 `PlanetResult(total_matches, returned_count, planets)`다. `total_matches`는 조건을 만족한 전체 행성 수이고, `returned_count`는 표시한 목록 길이다. `Planet`은 행성명·항성명·발견 방법·연도·반지름을 담는다. Pydantic의 별칭으로 NASA 원본 열 이름을 읽고, 모델에 전달할 JSON에는 이해하기 쉬운 `name`, `host_star`, `discovery_method`, `discovery_year`, `radius_earth`를 사용한다.

모든 모델에 `strict=True`, `extra="forbid"`를 적용한다. CSV의 연도와 반지름은 명시적으로 정수·실수로 변환한 후, **검색 조건에 맞지 않는 행까지 모두** `Planet.model_validate()`로 검사한다. 반환 건수와 목록 길이의 관계도 검사한다.

### 코드 흐름

1. `main()`의 `input()`: 한 요청을 받는다. 빈 입력은 모델 호출 없이 안내 후 종료한다.
2. `bind_tools()`와 시스템 지시: 반지름 상한이 있으면 검색하고, 필수 조건 누락은 질문한다. 선택 조건 생략은 기본값으로 처리한다.
3. `SearchArgs.model_validate(call["args"])`: 실제 모델 인자를 검사하고 `model_dump()`로 도구에 전달한다. `args_schema`에도 같은 입력 모델을 연결했다.
4. `search_exoplanets()`: 실제 CSV를 읽고 행을 변환·검증한 뒤 조건 검색, 정렬, 표시 개수 제한을 수행한다.
5. `PlanetResult` 생성·`model_validate()`: 반환 구조와 건수를 확인한다. 검사 실패나 CSV 파일 누락·손상은 예외로 중단하며 빈 검색 결과로 바꾸지 않는다.
6. `ToolMessage`: 검증된 결과를 `model_dump_json()`으로 변환해 원래 `call["id"]`에 연결한다. 원래 모델 응답도 대화에 남긴다.
7. `model.invoke(messages)`: 실제 검색 결과로 최종 답변을 작성한다. 확인 질문 후에는 다시 실행해 전체 요청을 입력한다.

### 실행 방법
