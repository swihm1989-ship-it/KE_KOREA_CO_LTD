# 사진 인화 비용을 도구로 계산하기

01의 도구 호출 왕복과 02의 입력·반환 검사를 다른 문제에 적용한다. 사진 크기와 수량으로 인화 비용을 계산하는 도구를 직접 만들고, 모델이 요청한 값과 실제 계산 결과를 확인한 뒤 안내까지 연결한다. 한 Python 파일에 단계별로 코드를 더해 간다.

## 문제와 계산 기준

아래 가격표로 사진 인화 비용을 계산한다. 수량은 1장부터 20장까지이며, 총금액은 장당 가격과 수량을 곱한 값이다.

| 사진 크기 `size` | 장당 가격 |
| --- | --- |
| `4x6` | 400원 |
| `5x7` | 700원 |

먼저 다음 세 요청을 한 번에 하나씩 확인한다.

| 요청 | 원문에 있는 값 | 기대하는 동작 |
| --- | --- | --- |
| “5x7 사진 6장 인화 비용을 알려 줘.” | `size="5x7"`, `quantity=6` | 도구로 계산하고 4,200원을 안내한다. |
| “4x6 사진 3장 인화 비용을 알려 줘.” | `size="4x6"`, `quantity=3` | 도구로 계산하고 1,200원을 안내한다. |
| “5x7 사진 인화 비용을 알려 줘.” | `size="5x7"`, 수량 없음 | 수량을 묻고 도구는 실행하지 않는다. |

안내의 대상은 비용 견적이다. 인화 주문을 접수하거나 처리 완료를 안내하는 단계는 포함하지 않는다.

## 1. 입력과 반환값을 먼저 정한다

가격표를 사전으로 적고, 요청 문장은 `REQUEST`에 적는다. 모델이 요청에서 크기와 수량을 골라 도구 인자를 만들도록 연결한다. 별도의 정답 사전을 실행 코드에 작성하지 않는다.

실행 전에 위 표의 기대 결과를 읽고, 실행 후에는 모델이 만든 크기·수량을 원문과 대조한다. 원문에 수량이 없으면 모델이 확인 질문을 해야 하며, 계산 도구의 정상 입력에 `None`을 넣지 않는다.

도구의 반환값은 다음 네 키를 갖는 사전으로 정한다.

| 키 | 뜻 | 첫 요청의 값 |
| --- | --- | --- |
| `size` | 사진 크기 | `"5x7"` |
| `quantity` | 인화할 장수 | `6` |
| `unit_price_won` | 가격표의 장당 가격 | `700` |
| `total_fee_won` | 장당 가격 × 장수 | `4200` |

## 2. 함수를 만들고 도구만 먼저 실행한다

크기와 수량을 받는 함수를 작성한다. 타입 힌트와 짧은 docstring을 적고 `@tool`로 도구를 만든다. 함수 안에서는 가격표에서 단가를 찾아 네 키의 사전을 반환한다.

먼저 `arguments`에 크기와 수량을 넣어 `도구.invoke(arguments)`를 실행한다. 전달한 인자와 반환값을 출력하고 첫 두 요청의 금액을 직접 계산해 대조한다. 이 단계는 모델을 호출하지 않는다.

## 3. 모델의 호출 요청과 실제 실행을 연결한다

01의 왕복 흐름을 이어 붙인다. 모델 설정은 수업과 같은 다음 두 줄을 사용한다.

```python
load_dotenv()
model = ChatOpenAI(model=os.environ["OPENAI_MODEL"])
```

`bind_tools([작성한 도구])`로 도구를 연결하고 `REQUEST`를 전달한다. 지시에는 크기와 수량이 모두 있을 때 계산하며, 빠진 값은 임의로 채우지 않고 질문하도록 적는다.

`response.tool_calls`를 출력해 도구 이름과 `args`를 읽는다. 호출 요청이 있으면 `args` 사전으로 도구를 실행한다. 원래 모델 응답을 대화에 추가하고, 실행 결과를 같은 호출의 `call["id"]`와 연결한 `ToolMessage`로 돌려준 뒤 최종 안내를 받는다. 호출 요청이 없으면 `response.text`를 읽는다.

## 4. 실행 앞뒤에 검사를 더한다

02의 `model_validate()`와 `model_dump()`를 사용해 다음 순서로 확인한다.

1. 입력 모델에 `ConfigDict(strict=True, extra="forbid")`를 설정한다. `size`는 `Literal["4x6", "5x7"]`, `quantity`는 `Field(ge=1, le=20)`를 적용한 `int`로 정한다. 도구의 `args_schema`에도 이 입력 모델을 연결한다.
2. 모델이 만든 `args`의 형식과 허용 범위를 검사한다. 크기·수량이 규칙에 맞지 않으면 도구를 실행하기 전에 중단한다.
3. 검사한 인자를 `model_dump()`로 꺼내 도구를 실행한다.
4. 반환 모델에도 엄격한 타입과 추가 키 금지를 설정하고, 위의 네 키를 모두 검사한다. 크기·수량은 입력 모델과 같은 허용 범위를 사용하고, 두 금액은 `int`로 정한다.
5. 반환된 크기·수량이 실제 실행한 인자와 같은지 비교한다. 단가는 실행한 크기의 가격표와 같고, 총금액은 그 단가에 실행한 수량을 곱한 값인지 확인한다. **금액이 정수라는 검사만으로 계산이 맞다는 뜻은 아니다.**
6. 검사를 통과한 결과만 `ToolMessage`로 전달한다. 검사 실패는 예외로 중단하고 최종 안내에 사용하지 않는다.

`ge=1`은 1 이상, `le=20`은 20 이하라는 뜻이다.

이 검사는 형식·범위·실행 인자와 결과의 일치를 확인한다. 모델이 원문의 크기·수량을 정확하게 해석했는지는 별도로 읽어 확인한다. 원문과 다른 값이어도 허용 범위 안이면 형식 검사를 통과할 수 있다.

검사를 확인하려고 모델이 반드시 오류를 내게 만들 필요는 없다. 정상 인자나 반환 사전을 복사해 수량을 문자열로 바꾸거나 총금액만 잘못된 정수로 바꾸고, 해당 검사에서 멈추는지 확인해도 된다.

## 5. 상황을 바꾸어 결과를 확인한다

세 요청을 한 번에 하나씩 실행하며 다음을 확인한다.

- 첫 두 요청은 원문의 크기·수량으로 도구를 한 번 실행하고, 검사한 단가·총금액을 근거로 안내한다.
- 수량이 빠진 요청은 도구 호출·실행 없이 수량을 묻는다. 임의 수량이나 총금액을 만들어 안내하지 않는다.
- 입력을 바꾸면 모델의 `args`, 검사 후 인자, 함수 반환값, 최종 안내가 어떻게 이어지는지 읽는다.

추가로 경계 사례 한 개를 직접 설계한다. 수량 범위, 지원하지 않는 크기, 잘못된 값의 형식, 실행 인자와 다른 반환 크기·수량 중 하나를 골라 **실행 전에 기대하는 동작을 먼저 적고** 결과와 대조한다. 인자나 반환 사전을 직접 바꾸어 검사하는 사례도 가능하다.

완성한 코드에서 `@tool → tool_calls 인자 검사 → 실제 실행 → 반환·금액 검사 → ToolMessage → 최종 안내`의 연결을 설명하고, 각 요청이 어디서 계산하거나 질문하거나 중단하는지 확인한다.

### 연결 흐름

1. `@tool(args_schema=PhotoPrintArgs)`가 사진 크기와 수량의 입력 규칙을 모델에 제공한다. 모델이 요청 문장을 해석하며, 문장별 정답 사전은 사용하지 않는다.
2. `response.tool_calls`에서 도구 이름과 인자를 출력한다. 입력은 `model_validate()`로 엄격한 타입·범위·추가 키를 검사하고, `model_dump()`로 꺼내 실제 도구를 실행한다.
3. 반환값은 `PhotoPrintResult`로 검사한다. 이 모델은 입력 모델의 엄격한 설정과 크기·수량 범위를 상속하고 두 정수 금액을 추가한다.
4. `validate_result()`가 반환 크기·수량과 실행 인자를 비교하고, 단가 및 총금액을 가격표와 대조한다. 검사가 실패하면 예외로 중단하므로 `ToolMessage`와 최종 안내까지 진행하지 않는다.
5. 검사를 통과한 결과만 JSON으로 변환하여 원래 호출 ID에 연결한 `ToolMessage`로 전달한다. 대화에는 원래 모델의 호출 요청도 포함되며, 모델이 실제 계산 결과를 읽고 최종 견적을 안내한다.
6. 도구 호출이 없으면 도구를 실행하지 않고 첫 응답의 `response.text`를 출력한다.

### 실제 관찰 (2026-10-27)

실행 전에 위 과제 표의 기대값을 확인했고, 실행 후 모델 인자를 원문과 대조했다.

| 요청 | 모델의 args / 호출 횟수 | 검사된 반환값 | 실제 최종 안내 |
| --- | --- | --- | --- |
| 5x7 사진 6장 인화 비용을 알려 줘. | `{"size": "5x7", "quantity": 6}` / 1회 | 단가 700원, 총금액 4,200원 | 5x7 사진 6장 인화 비용은 **4,200원**입니다. |
| 4x6 사진 3장 인화 비용을 알려 줘. | `{"size": "4x6", "quantity": 3}` / 1회 | 단가 400원, 총금액 1,200원 | 4x6 사진 3장의 인화 비용은 **1,200원**입니다. |
| 5x7 사진 인화 비용을 알려 줘. | `tool_calls=[]` / 0회 | 실행하지 않음 | 몇 장 인화하시나요? 수량은 1~20장으로 알려 주세요. |

첫 두 요청은 모델 인자, 검사 후 인자, 반환 크기·수량이 원문과 일치했다. 수량이 없는 요청은 임의 수량이나 총금액을 만들지 않고 질문했다. 세 요청 모두 주문 접수·처리 완료를 안내하지 않았다. 위 안내 문구는 실제 실행 결과이며, 재실행 시 표현은 달라질 수 있다.

### 경계 사례와 검사 결과

경계 사례는 정상 반환값의 `total_fee_won`만 정수 `4100`으로 바꾸는 경우다. 실행 전 기대는 “타입 검사는 통과하지만 계산 검사에서 중단하고 최종 안내에는 사용하지 않는다”로 정했다. `--local` 실행 결과 `ValueError: 반환 총금액이 단가 × 수량과 다릅니다.`가 발생해 기대와 일치했다. 이 관찰용 모드만 의도된 예외를 잡아 출력하며, 모델 실행 경로에서는 검사 예외를 잡지 않는다.

추가 자동 검증 4개도 모두 통과했다. 정상 견적과 수량 경계 1·20장, 문자열·불리언·누락·범위 밖 수량과 미지원 크기·추가 키의 차단, 잘못된 단가·총금액과 실행 인자 불일치 차단, 반환 타입·추가 키 검사를 확인했다.

형식 검증만으로 원문 해석이 정확하다고 보장할 수는 없다. 따라서 모델의 인자가 원문의 크기·수량과 같은지도 실행 로그에서 별도로 확인했다.
