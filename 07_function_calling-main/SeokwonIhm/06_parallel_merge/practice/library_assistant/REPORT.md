# 도서관 병렬 조회 검증 기록 · 2026-10-29

실제 제공 JSON을 읽어 테스트했다. 외부 모델 API와 실제 도서관 접속은 사용하지 않았다. 도서 대화 앱은 기존 `.env`의 모델 설정으로 실행할 수 있으며, 아래 대화 테스트는 고정된 모델 응답을 사용해 메시지 연결만 검사했다. 실제 모델의 자연어 분류와 최종 문장은 이번 검증 범위에 포함하지 않았다.

## 예상 판정과 실제 결과

다음 여섯 조건을 순차·병렬 상한 1·병렬 상한 2로 각각 실행했다. 총 18건 모두 자료·오류·지점 연결과 예상 판정이 일치했다. 전체 요청·작업별 시작/종료/소요 시간·병합 결과·모델 없는 정형 안내는 `verification.json`에 있다.

| 제목 / 시나리오 | 예상·실제 판정 | 중앙 | 동부 | 서부 |
| --- | --- | --- | --- | --- |
| 파이썬 첫걸음 / normal | complete | 2권 | 0권 | 1권 |
| 데이터 분석 입문 / normal | complete | 0권 | 0권 | 0권 |
| 비동기 프로그래밍 / normal | complete | 1권 | 미등록 | 0권 |
| 우주 항해 입문 / normal | complete | 미등록 | 미등록 | 미등록 |
| 파이썬 첫걸음 / east_error | partial | 2권 | 오류·미확인 | 1권 |
| 파이썬 첫걸음 / all_error | failed | 오류·미확인 | 오류·미확인 | 오류·미확인 |

미등록은 정상 조회 결과이며 `available_count=null`이다. 0권은 등록된 도서의 정수 권수다. 오류는 `result=null`로 기록했으며 실패한 지점을 미등록이나 0권으로 바꾸지 않았다. 기준 시각은 원본 `2026-10-29T09:00:00+09:00`을 유지했다.

## 실행 구간과 시간

`verification.json`의 첫 번째 책·normal 실행에서 관찰한 값이다.

| 모드 | 전체 실행 시간 | peak_active |
| --- | --- | --- |
| 순차 | 0.630353초 | 1 |
| 병렬, 상한 1 | 0.629065초 | 1 |
| 병렬, 상한 2 | 0.312132초 | 2 |

상한 2에서는 중앙과 동부의 실행 구간이 겹쳤고, 동부 종료 후 서부가 시작했다. 지점별 실제 기록은 중앙·동부·서부의 입력 순서로 반환되었다. 작업 구간 시각은 UTC, 자료 기준 시각은 원본의 +09:00 오프셋이다. 총시간은 관찰값이며 모든 환경에서 같은 속도 향상을 보장하지 않는다.

`compare_execution.py`의 기본 순차/병렬 비교도 별도로 실행해 `comparison_results.json`에 기록했다. 모델 호출 수는 0, 각 비교의 내부 작업 수는 3이다.

## 회귀 테스트

`python -m unittest discover -v`: **15개 통과**.

- 실제 JSON의 권수, 등록 0권과 미등록의 구별, 전체 미등록의 complete 판정
- 부분 실패의 성공 자료 보존, 전체 실패의 미확인 처리
- 순차와 병렬의 같은 반환·오류, 동시 상한 1/2와 실행 구간 겹침
- 취소의 상위 전파, 빈 제목·잘못된 타입·시나리오·상한 거부
- 모순된 반환과 누락된 지점 기록 거부
- 모델에 제목 인자만 공개하고 도구 1회가 내부 작업 3개를 반환하는지 확인
- 제목 질문에는 ToolMessage가 없고, 보충 답변 뒤 원래 호출 ID의 ToolMessage 하나만 생성
- 같은 대화의 새 제목을 새로 조회하고 이전 권수를 재사용하지 않음
- 도구 없는 응답의 메시지 연결, 모델이 요청한 가짜 제목·복수 호출의 실행 전 거부

대화 테스트에서 “도구 없이 일반 설명/예약 미지원 안내”라는 선택은 고정된 모델 응답으로 주었다. 모델이 실제 질문을 올바르게 분류하는지는 `app.py` Run 후 확인해야 한다.

## 코드에서 확인할 부분

- 병렬 실행: `batch.execute_batch()`의 `asyncio.gather()`와 `async with semaphore`. 지점별 JSON 조회는 `tools.lookup_branch()`이며 비동기 지연과 `asyncio.to_thread()`를 사용한다.
- 합류 후 판정: `batch.merge_results()`. 세 작업이 끝난 후만 결과를 분류하며 지점 식별자와 제목을 검사한다.
- 모델에 반환: `app.answer()`. 원래 AIMessage를 유지하고, 실제 병합 결과를 원래 호출 ID의 ToolMessage 하나로 연결한다. 내부 작업에는 가짜 모델 호출 ID를 만들지 않는다.

기존 수업 파일, 제공된 JSON, 기존 환경 파일은 수정하지 않았다. 새 앱의 실습 범위는 조회와 안내이며 예약·대출 저장은 수행하지 않는다.
