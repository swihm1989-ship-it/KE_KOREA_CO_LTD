# 도서관 병렬 조회 구현 계획

기준: ../README.md, 사용자 요청. 기존 수업 파일과 JSON은 수정하지 않는다.

1. contracts.py에서 제목·지점 자료·시나리오·작업 기록·병합 반환을 검사한다.
2. tools.py에서 제목을 정확히 일치시켜 JSON을 읽는다. 모델에는 compare_library_stock(title) 하나만 공개한다. 시나리오와 상한은 Python 설정이다.
3. batch.py에서 Semaphore 안에서 실행 시간을 측정하고 gather로 세 지점을 합류한다. 일반 예외만 작업 오류로 기록하고 취소는 전파한다. 합류 후 권수·미등록·오류와 complete/partial/failed를 판정한다.
4. prompts.py와 app.py는 도서명 보충 질문을 같은 이력에 연결하며, 새 제목은 새 조회한다. 모델 호출 하나에 내부 작업 세 개와 원래 ID의 ToolMessage 하나를 연결한다.
5. compare_execution.py로 순차·병렬의 같은 자료/오류·실행 구간·동시 상한을 검증하고 기록한다. 테스트는 일반/부분/전체 실패, 0권/미등록, 취소, 입력·반환 오류, 대화 이력을 포함한다.

병렬 상한은 기본 2, 비교 시 1 또는 2. 실시간 도서관 조회·대출·예약 기능은 제공하지 않는다. 모델 API를 실행하지 않는 로컬 검증부터 완료하고 실제 모델 검증 여부는 기록에서 구분한다.

완료: 다섯 구현 파일, 비교 실행 파일, 테스트, 안내 문서를 추가했다. 로컬 테스트 15개와 실제 JSON 비교 실행 18건이 통과했다. 기본 순차/병렬 비교도 실행했다. 상세 자료는 REPORT.md, verification.json, comparison_results.json에 저장했다. 모델 API는 호출하지 않았다.
