### ERR-01 / P1 — 통화를 변경하면 이전 카탈로그 단가가 남는다

위치: `Quotation_KEKOREA/agent/pricing.py:204`, `Quotation_KEKOREA/app.py:704`, `Quotation_KEKOREA/app.py:842`.

재현 조건:

2. 수량 10의 PI에 카탈로그 가격을 적용한다.
3. 단가 숫자는 그대로 두고 문서 통화를 **EUR**로 바꾼다.
4. 카탈로그 가격을 다시 검증한다.

실제 결과:

```text
currency = EUR
unit_price = 10
master_price = false
Total amount = EUR 100.00
Create PDF enabled = true
```

EUR 가격을 찾지 못하면 `master_price`만 false가 되고 기존 `unit_price`, `product_id`, 가격 출처가 남는다. 미등록 EUR 가격/마스터 불일치 경고가 실제 생성 차단 목록에 포함되지 않아 버튼이 활성화된다. **환율 변환이 수행된 것이 아니다.**

기대: 적합한 통화의 가격을 찾지 못하면 기존 카탈로그 가격을 새 통화 가격처럼 사용하지 않아야 한다. 적법한 거래 가격이 확인되기 전에는 금액 확정/파일 생성을 막아야 한다.

이번 검토에서는 수정하지 않았다. 통화 변경 후에는 단가의 통화·출처를 별도로 대조해야 한다.

### ERR-02 / P1 — 상품명의 소수점이 제거되어 다른 숫자와 일치한다

위치: `Quotation_KEKOREA/agent/product_matching.py:15`, `:20`.

| 카탈로그 | 입력 | 실제 결과 |
| --- | --- | --- |
| `COLLAGEN 5000 SERUM` | `COLLAGEN 50.00 SERUM` | 일치, 추가 확인 없음 |
| `C.P 50` | `C.P 5.0` | 일치, 추가 확인 없음 |

`_compact`가 소수점을 삭제하고, `_pattern`이 각 숫자 사이의 구두점을 허용한다. 따라서 의미가 다른 `50.00`과 `5000`, `5.0`과 `50`이 같아진다. 가상 가격을 넣은 종단 검증에서도 단가와 `master_price=true`가 설정됐고 추가 확인이 없었다.

기대: 일반적인 이름 구두점과 의미 있는 숫자의 소수점을 구분해야 한다. 숫자가 들어간 정식 상품명 자체가 문제인 것은 아니다. 정식 표기는 아래 기본 행렬에서 정상 인식됐다.

고유 코드 `S-1`, 정식 이름 `Natural Perfect Sun Cream SPF50+ PA+++`, 용량 70g인 가상 상품에서 `S-1`, `SKU: S-1`, 또는 이름 없이 구조화된 `product_code=S-1`은 미인식된다. 코드 전용 복구 경로가 있더라도, 이름에 없는 SPF/PA 등급을 카탈로그 이름과 비교해 탈락시킨다.

### 재발 가능한 미지원 표기: 구분자 없이 완전히 이어 붙인 이름

이 항목은 잘못된 상품 가격을 자동 확정한 것이 아니라 **보수적으로 미인식한 범위**다.

- `상품명코드`: 131개 중 **127개 미인식**, 4개 일치.

현재 매칭은 잘못된 긴 단어 속 부분 일치를 막기 위해 경계를 요구한다. OCR이 공백/괄호를 없애 완전히 붙이면 여전히 수동 확인이 필요하다. 모든 형태의 코드/숫자 혼합을 지원한다고 안내하면 안 된다.

## 11. 후속 기능 — PI 샘플 수동 입력 (2026-11-03)

## 12. 후속 기능 — PDF 공통 입력 및 PI 원본의 CI 적용 (2026-11-03)

PO·PI·CI·PL·CIPL의 공통 업로드에 PDF를 추가하고, 첨부 PI 이미지/PDF의 거래값을 기존 CI 생성기로 전달하는 별도 모듈을 추가했다. 기존 CI PDF/Excel/HTML 생성 코드와 PI 전용 은행 출력 분기는 수정하지 않았다.

개발 및 검토 중 아래 사례를 재현하고 회귀 테스트로 고정해 보완했다.

- PDF를 이미지 미리보기에 전달해 발생하는 오류: PDF와 이미지 미리보기를 분리한다.
- PI 원본의 할인율이 기본 0%로 덮어써지는 문제: PI 가져오기에서는 원본 가격/할인을 유지하고 원본 행 금액·총액을 비교한다.
- `Bank:`·`Beneficiary:`·`A/C:`·`T/T` 등 짧은 금융 표기가 PI 비고를 통해 CI로 넘어가는 문제: 가져오기에서 제외한다. 통화 충돌 경고는 값이 노출되지 않는 확인 경고로 보존한다.
- `Create CI from the attached PI` 같은 영어 변환 요청이 PI 생성 명령으로 오인되는 문제: 명시적인 변환 요청을 구분한다.
- 원본 근거 없는 0원 추출값이 통과하는 문제: 0원/FOC 근거를 요구하고 가격·수량 인용 근거 충돌도 가져오기 생성 차단에 포함한다. 일반 상품의 가격 검증은 유지한다.
- 원본에 별도로 반복 인쇄되지 않는 파생 출고수량과 생략된 0% 할인/증정 0을 실제 가격 근거 누락과 구분한다. 유상·증정·계산 출고수량의 일치 검증은 유지한다.

기존 이미지 전용 화면 문구·첨부 지우기·메뉴 복귀 동작과 포장 합계 승인을 보존했다. 실제 API 요청은 하지 않고 합성 자료·가짜 API 응답·실제 로컬 파일 생성으로 검증한다. 운영 배포/실제 OCR 검증은 별도이며, 이번 추가가 최초 감사의 다른 항목을 해결했다는 의미는 아니다.
