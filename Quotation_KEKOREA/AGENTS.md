# Quotation KEKOREA 변경 보호 지침

이 지침은 이 디렉터리 전체에 적용한다. README의 현재 동작을 계약으로 취급한다. 사용자에게서 해당 동작을 변경하라는 명시적 요청이 없는 한, 다른 작업을 하면서 아래 동작을 바꾸거나 제거하지 않는다. 필요한 버그 수정은 해당 동작을 유지하는 최소 범위로 수행한다.

## 반드시 보존할 동작

- **명시적 수량 0:** 숫자/문자열 0은 유효한 주문수량이다. 행을 유지하고 행 금액을 0으로 계산한다. 누락값·음수·비숫자·NaN/Infinity는 오류다. 숫자 0을 거짓값으로 취급해 다른 필드로 대체하지 않는다. 단가 양수 검증과 혼동하지 않는다.
- **PDF 페이지:** 상품은 실제 공간이 부족할 때만 다음 페이지로 이동한다. 하단 영역에 상품 한 줄을 동반시키려고 강제로 이동하지 않는다. 계좌정보 6개 항목과 회사 명판·직인은 한 페이지의 하나의 묶음이며 절대 분할하지 않는다. 현행 합계·REMARK 포함 하단 묶음도 유지한다.
- **누락 정보 입력:** 빈 필수 항목을 PDF의 임시 문구로 넘기지 말고 화면에서 입력받는다. 선택 항목의 N/A는 명시적으로 입력받는다. 메뉴 이동 시 입력을 보존하고 새 주문에는 이전 주문 값을 섞지 않는다. 문서 내용 수정 후 이전 다운로드를 다시 노출하지 않는다.
- **가격·통화:** PO에는 검증된 ECLADO KRW 매입가격을 사용하고, PI는 Dear Glow 판매가격을 사용할 수 있다. CI는 첨부 PI의 거래가격을 그대로 사용하며 PI가 없으면 카탈로그 가격을 대체 적용하지 않고 내보내기를 막는다. CI/PL 상품 매칭은 제품 확인에만 사용하며 가격을 적용하지 않는다. 명시된 거래 통화를 임의로 변경하지 않는다. Decimal과 KRW/USD 반올림 순서를 유지한다.
- **ECLADO 인식:** `eclado`/`ECLADO CO. LTD`/`에끌라도`/`에끌라두` 및 공백·대소문자·구두점 변형을 같은 공급처로 인식한다. 법인명 원문은 바꾸지 않는다. 다른 한글 공급처를 공급처 누락으로 취급하지 않는다. 일부 상품 미일치 때문에 정확히 일치한 상품까지 가격 조회를 건너뛰지 않으며, 미일치 상품에 가격을 추측해 넣지 않는다.
- **PL/CIPL 합계 승인:** 원본/계산 합계 비교표와 명시적 수정 승인을 유지한다. 승인 시 원본 합계를 보존하고 계산 가능한 합계만 적용한다. PCS/KG 등 다른 단위를 합치지 않고, 품목/원본 합계 수정 후에는 다시 승인받는다. 잘못된 행 값·충돌한 단위·컨테이너 수 오류를 합계 승인으로 무시하지 않는다. 컨테이너 개수와 FT 규격을 곱하지 않으며 실제 행/상업송장 수량은 합계 수정으로 변경하지 않는다.
- **직인·비밀정보:** 직인은 비공개 Supabase 버킷과 원본 SHA-256 검증을 사용한다. 키와 원본 직인을 Git/README/로그에 넣지 않는다. 큰 Base64 Secret을 다시 필수로 만들지 않는다.
- **공통 문서 규칙:** 발행일은 생성 시점 Asia/Seoul 날짜, PO 구매자는 KE KOREA, 판매 문서 판매자는 KE KOREA다. SHIP TO를 다른 주소에서 추측하지 않는다. 실제 발주/발송은 자동 수행하지 않는다.

## 수정·검증 절차

1. 관련 코드, README, 기존 테스트를 먼저 읽고 오류를 재현한다. 화면의 `Cannot calculate`만 보고 원인을 단정하지 않는다.
2. 변경할 동작을 검증하는 회귀 테스트를 먼저 추가한다. 기존 보호 테스트를 삭제·약화·skip 처리해 성공시키지 않는다.
3. 기능 수정은 필요한 부분으로 한정한다. 페이지/서식, 가격 정책, 추출 규칙, 직인, 입력 상태를 서로 관계없는 변경에 함께 수정하지 않는다.
4. 저장소 루트에서 `uv run --with streamlit --with pymupdf python -m unittest discover -s Quotation_KEKOREA/tests`와 `git diff --check`를 실행한다. Streamlit AppTest가 생략된 결과를 전체 화면 테스트 성공으로 보고하지 않는다.
5. 검증을 통과한 변경사항, 사용자에게 보이는 동작, 실제 수행한 배포 검증 범위를 README에 갱신한다. 미확인 상태를 완료로 기록하지 않는다.
6. 배포가 요청된 작업은 GitHub 반영만으로 끝내지 말고 실제 앱의 해당 경로를 확인한다. 가상 자료를 우선 사용한다. 원본 주문 자료의 외부 전송이 승인에서 거절되면 다른 경로로 전송하지 말고 허용된 로컬 검증을 마친 뒤 사용자 승인을 요청한다.

## 2026-11-06 TASTE 계약서 UI 및 README 동기화 이후 README 자동 동기화 규칙

기능을 추가·수정·삭제할 때 같은 커밋에서 다음 다섯 파일을 함께 점검하고 필요한 내용을 고친다.

1. `../README.md` : 프로젝트 전체 기능/링크/배포 상태
2. `README.md` : 설계·변경 이력·테스트 결과
3. `README_CONTRACTS.md` : 계약 기능 실제 구현/제한사항
4. `Team/README.md` : 팀 구현·연동·위험 사항
5. `Presentation/README.md` : 시연할 수 있는 실제 기능과 검증 상태

변경 전 코드 설명이 더 이상 맞지 않으면 그 설명을 최신 동작으로 대체하고, 제거된 기능은 현재 동작 목록에서 빼거나 역사 기록으로 명확히 옮긴다. **코드만 바꾸고 README 업데이트를 생략하지 않는다.** 운영 확인이 안 된 경우 '미확인'을 유지하며, 과거 회귀 실패를 현재 실패로 단정하지 않는다.

`../scripts/check_readme_sync.py`는 스테이징된 프로젝트 실행 코드가 있으면 다섯 README가 같은 커밋에 모두 포함되는지 확인한다. `.githooks/pre-commit` 사용 시 로컬 커밋을 자동 검사한다. 이 검사는 문서의 진실성까지 보장하지 않으므로 사람의 리뷰와 테스트를 대체하지 않는다.
