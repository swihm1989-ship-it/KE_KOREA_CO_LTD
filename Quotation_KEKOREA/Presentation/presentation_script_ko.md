# KE KOREA AI 업무 자동화 에이전트 — 15분 발표 + 15분 시연 (1차 수정안)

> 기준: 2026-11-13까지 저장소의 구현 및 README 변경 이력. 발표 날짜: 2026-11-17. 발표용 자료이며 **운영 성공을 보장하지 않는다**. 기존 5분 발표를 대체하는 초안이다.

## Part A — 발표 15분

### 00:00–03:00 | 개발의 이유와 회사 업무 가치
안녕하세요. 오늘은 KE KOREA의 AI 업무 자동화 에이전트를 소개하겠습니다. 무역업무는 이메일 한 통에서 시작해 견적, 주문, 계약, 출하 서류로 이어집니다. 같은 회사명·제품·수량·가격·결제조건을 PI, PO, CI, PL과 계약서에 반복 입력하다 보면 시간이 들고 문서 간 불일치도 발생합니다.

그래서 목표를 단순한 AI 계약서 생성기가 아니라 **메일 수신부터 거래조건 추출, 부족정보 보완, 문서 검토와 출력까지 이어지는 하나의 업무 흐름**으로 잡았습니다. AI가 사람을 대신해 계약을 확정하는 것이 아니라, 반복 입력과 초안 작성을 줄여 담당자가 거래 판단에 집중하도록 만드는 것입니다.

### 03:00–05:00 | 시스템 개요와 이메일 추출
실제 업무를 예로 들겠습니다. 해외 바이어가 이메일로 “Please provide PI for 1,000,000 solar cells, USD 0.225 per piece, EXW Jincheon”이라고 보냈다고 가정하겠습니다.

MASTER 메일함에서 해당 메일을 선택하고 **AI 업무 요청으로 이동**을 누르면 제목·본문과 제가 선택한 첨부, 문서 종류가 업무 화면으로 넘어갑니다. 이동 자체가 AI 호출은 아닙니다. 제가 AI 사용을 승인하면 거래조건 추출이 시작됩니다.

수량 100만 장, 단가 0.225달러라면 거래금액은 225,000달러입니다. Buyer 이름이나 연락처가 빠져 있다면 AI가 지어내는 대신 같은 화면에서 입력하도록 합니다. 입력값이 바뀌면 이전 검토·승인·출력 파일도 무효화됩니다. 이것이 실무에서 특히 중요했던 개선입니다.

### 05:00–07:00 | LangGraph: 업무 순서를 연결
LangGraph는 AI 작업을 단계별로 연결하는 도구입니다. 일반 챗봇은 질문에 답하지만 계약 작성은 거래조건 분석, 조항 검색, 초안 작성, 누락·충돌 검사, 필요 시 보완이 이어져야 합니다. 각 단계를 노드, 연결을 엣지라고 생각하면 됩니다. 실제 계약 분석과 초안 생성에 적용했습니다. 단, 메일함·모든 무역문서가 동일한 그래프를 통과하는 것은 아닙니다.

### 07:00–10:30 | RAG, Chunk, Embedding, Vector
회사의 과거 계약서를 활용하려면 AI가 필요할 때 관련 조항을 찾아야 합니다. 이것이 RAG, 즉 검색 증강 생성입니다. 긴 계약서를 결제·보증·해지 같은 작은 조항 단위인 청크로 나눕니다. Embedding은 청크의 의미를 숫자 배열로 바꾸고, Vector는 그 숫자 배열입니다. 이 앱의 기본 임베딩 모델은 text-embedding-3-small, 벡터는 512차원입니다.

예를 들어 '계약 종료 후 수수료 지급'과 '해지 이후 소개 거래에 대한 보수'는 표현이 달라도 의미가 비슷합니다. 벡터의 코사인 유사도와 키워드를 함께 사용하면 관련 참고 조항을 찾는 데 도움이 됩니다. 벡터는 Supabase JSONB에 저장하고 Python에서 비교합니다. pgvector나 FAISS를 쓴다고 소개하지는 않겠습니다.

최근에는 과거 계약서의 원문과 조항 위치를 복구하고, 서로 다른 계약서의 조항과 앞뒤 문맥을 비교하는 RAG 2.0 경로도 구현했습니다. 다만 원문 전체가 자동으로 AI에 공개되는 것은 아닙니다. 관리자가 검토·비식별화·승인한 참고 지식만 사용합니다. 당시 승인 메모 143개 중 35개만 임베딩이 확인되어 나머지 백필은 별도 검증 대상입니다.

### 10:30–12:30 | Supabase, Revision, 사람의 승인
Supabase는 계약, 대화, 수정 이력과 비공개 원문을 저장하는 역할입니다. AI가 계약서를 학습해 모델 자체가 바뀌는 것이 아니라 저장된 지식을 다시 검색합니다. 계약서에서 문장을 선택해 수정 메모를 남기고, 제안과 기존 문장을 비교한 뒤 승인하면 새 revision이 기록됩니다. AI 제안과 최종 확정을 분리한 것입니다.

### 12:30–14:00 | 기존 회사 양식과 출력
PI·PO·CI·PL은 기존 KE KOREA 양식을 유지합니다. 최근에는 문서별 부족정보를 하나의 화면에서 보완하고, 일부 정보가 미확정이면 사용자가 승인한 뒤 해당 칸을 공란으로 출력할 수 있게 했습니다. 하지만 계산 오류나 실제 거래조건 충돌까지 무시하지는 않습니다. 계약서 DRAFT/FINAL은 별도의 검증과 승인 절차를 따릅니다.

### 14:00–15:00 | 정리
정리하면 이메일은 업무의 출발점, LangGraph는 계약 작업의 흐름, RAG와 임베딩은 회사 지식의 검색, Supabase는 기록과 참고자료 저장소입니다. AI가 작성과 분석을 돕고, Python 코드가 계산·검증을 지키며, 사람은 최종 판단과 승인을 합니다. 이제 메일에서 문서 출력까지 실제 화면으로 보여드리겠습니다.
