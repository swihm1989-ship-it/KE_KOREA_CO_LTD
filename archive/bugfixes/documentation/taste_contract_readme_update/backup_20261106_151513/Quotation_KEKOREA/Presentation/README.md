# KE KOREA AI 문서 자동화 — 발표용 요약

> 발표용 핵심 메시지와 시연 흐름. 현재 코드와 운영 배포의 검증 상태는 구분합니다.

## 1. 프로젝트 목적

반복되는 해외무역·계약서 문서 작업을 AI 기반 초안 생성과 사람이 승인하는 검토 과정으로 단순화합니다. 모델은 입력 내용을 구조화하고 문장을 제안하며, 가격 계산·필수값 검증·발행 판단은 별도 규칙과 사용자 확인을 거칩니다.

## 2. 발표 시 한눈에 보여줄 기능

| 분야 | 입력 | 처리 | 결과 |
| --- | --- | --- | --- |
| PO / PI / CI / PL | 텍스트, 이미지, PDF | OCR·구조화, SKU/용량 대조, DB 가격 조회, 누락·합계 검증 | 검토 후 PDF/Excel 초안 |
| 계약서 작성 | 거래 설명, 당사자·조건표, 참고 PDF/DOCX | 계약 유형 선택, 한국어/영어 초안, 문장 메모 및 변경 비교 | revision 기록, DOCX/PDF 초안 |
| 계약서 기록 | 저장 계약, 대화 메시지 | 계약별 History 조회, 이전 revision 복구 | 수정·검토 추적 |

## 3. 3분 발표 흐름

1. **문제(30초):** 반복 입력, 제품·가격 오류, 계약 문장 수정 이력 관리의 어려움.
2. **문서 자동화(60초):** 테스트 주문자료로 문서 종류 선택 → AI 추출 → 가격·누락 검토 → 결과 파일 미리보기.
3. **계약 기능(60초):** 저장된 계약 선택 → 대화 History → 문장 선택 및 메모 → 수정 전후 비교 → 적용 시 새 revision.
4. **통제와 마무리(30초):** 승인 없이는 중요한 변경이나 내보내기를 자동 확정하지 않음. 실제 계약 서명·발송은 수행하지 않음.

## 4. 품질 개선 사례

- 기존 견적서에서는 메뉴 이동 중 초안 소실, 상품 코드 인식과 가격 조회, 수량 0 처리, 포장 합계 승인 등을 회귀 테스트 대상으로 관리합니다.
- 계약 목록에서는 저장된 계약이 존재할 때 정의되지 않은 `options` 참조로 화면이 중단될 수 있는 오류를 발견하여, 계약 ID → 기록 매핑을 명시적으로 만드는 수정 패치를 준비했습니다.
- 삭제는 **X → 확인/취소**이며, 계약별 대화는 데이터 저장소에서 조회해 채팅 형식으로 표시합니다.

## 5. 데모 전 체크리스트

- 테스트용 합성 데이터만 사용. 비밀번호나 API 키, 민감 고객 계약은 시연에 넣지 않습니다.
- 로컬 전체 테스트 통과 및 `git diff --check` 확인 후 데모합니다. 이전 기록에는 `test_annotations_load_prices_without_bypassing_product_confirmation` 단일 실패가 보고되어 있으므로 재확인이 필요합니다.
- 계약서 저장·삭제는 운영 DB가 아니라 테스트 저장소로 시연합니다.
- GitHub에 커밋된 것과 실제 Render/Streamlit 배포를 구분합니다. 운영 앱은 로그인 없이 접근 가능하므로 실계약 시연은 금지합니다.

## 6. 검증 및 배포 현황 (2026-11-06)

이번 세션에서는 계약 목록의 `options` 오류를 소스 검토로 발견했습니다. GitHub 연결에 쓰기 권한이 없어 원격 저장 시도에서 HTTP 403이 발생했고, 전체 테스트와 실제 앱 구동은 실행 완료하지 못했습니다. **따라서 이번 수정은 검증·배포 완료 상태가 아닙니다.** 적용 후 실제 검사 결과를 기록해야 합니다.
