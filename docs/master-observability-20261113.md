# Master 실행 로그와 AI 모니터링

Master의 **관리자 모니터링** 메뉴는 기존 OIDC 인증 및 허용 계정 검증을 통과한 단일 관리자만 사용할 수 있다. 기존 계약/문서 서식, 메일 프로토콜, Supabase 직인 저장소, 승인 절차는 유지한다. Audit Log 기능은 추가하지 않는다.

## 수집 경계와 개인정보 보호

- 메일 수집, AI 거래조건 추출, 계약 분석/생성, PI/PO/CI/PL 생성 경계에서 시작/종료 JSON 이벤트를 만든다.
- 이벤트에는 무작위 실행/스팬 UUID, 작업 종류, 문서 종류(열거형), 시작/종료 시각(UTC), 단조 시계 처리시간, 상태, 고정 오류 분류, HTTP 상태, 허용된 모델명, 숫자 토큰/비용/기존 재시도 횟수만 들어간다.
- 함수 인수/반환값, 프롬프트, AI 응답 본문, 메일 내용/제목/주소/UID, 계약 내용/당사자, 사용자 계정, 파일명/내용/직인, 비밀번호/API 키/헤더, 예외 메시지/스택을 수집하지 않는다. 알 수 없는 모델명은 `other`, 예외는 고정 분류로 제한한다.
- 루트 로거, 외부 분석 SDK, LangSmith 전송, 프롬프트 콜백을 새로 활성화하지 않는다. 텔레메트리 JSON은 전용 저장소로만 보내며 stdout/공개 파일로 복제하지 않는다.

## 저장과 보존기간

`public.kekorea_telemetry_events`는 기존 KE KOREA Supabase 프로젝트의 별도 메타데이터 테이블이다. RLS를 켜고 `PUBLIC`/`anon`/`authenticated`의 모든 권한을 회수했다. 서버의 기존 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`만 사용한다. Streamlit 최상위 Secrets, 기존 auth 하위 설정, 환경변수 순서로 읽으며 직인/문서 설정을 변경하지 않는다.

보존기간은 **30일**이다. INSERT 트리거가 만료시각을 강제하고 요약/로그 조회에서 만료 데이터를 제외한다. `kekorea-telemetry-retention` pg_cron 작업이 매시 15분(UTC)에 만료 행을 삭제하므로 앱이 절전 중이어도 정리한다. 물리 삭제는 만료 후 최대 약 1시간 지연될 수 있다. 별도 식별 가능한 사업 데이터나 감사 이력은 없다.

업무 스레드는 최대 256개 이벤트 큐에 넣고 즉시 계속한다. 전용 데몬 스레드가 최대 64건씩 저장하며 통신 타임아웃은 2초, 저장 재시도는 배치당 최대 3회다. `event_id` 충돌 무시로 네트워크 재전송이 중복 집계를 만들지 않는다. 이 재시도는 AI 재호출이 아니다.

영구 저장이 불가능하면 최대 2,000개 JSON 이벤트를 30일 이내의 임시 메모리에 둔다. 서버 재시작 시 사라지며 자동으로 완전 복구되는 영구 큐가 아니다. 대시보드는 임시 모드, 대기/저장/누락 건수를 명시하고 부분 데이터임을 알린다. 저장 장애는 기존 메일/AI/문서 결과나 예외를 바꾸지 않는다.

## AI 집계와 비용의 의미

AI 호출 수는 실제 API 요청의 **종료 이벤트 1건**을 1회로 센다. 시작 이벤트와 화면 rerun은 집계하지 않는다. 토큰은 Responses API가 보고한 `usage.input_tokens`, `output_tokens`, `input_tokens_details.cached_tokens`만 사용한다. 누락값을 0으로 대체하지 않는다. 기존 인용 재검토/보호 코드 재번역만 `retry_count=1`로 표시하며 새 재시도 정책을 추가하지 않는다. 사용자의 별도 수동 실행은 새 실행 ID다.

비용 단가는 [OpenAI 공식 API 가격표](https://developers.openai.com/api/docs/pricing)를 2026-11-13에 확인한 표준 텍스트 토큰 기준이며 `pricing.py`에 버전으로 보관한다. 현재 명시적으로 확인한 GPT-6 Luna/Astra, GPT-6.1 Terra/Sol만 계산한다. 캐시 입력 할인은 적용하되 미등록 모델/날짜 스냅샷, 비표준 tier, 캐시 쓰기가 있으면 비용 미확인으로 남긴다. 도구/이미지/추가 서비스 요금, 별도 계약 할인/세금은 포함하지 않는 추정치다. 공급자 사용량이 불명확하면 대시보드는 확인된 소계와 미확인 호출 수를 분리한다. 실제 청구서를 대신하지 않는다.

## 검증과 운영 확인

`python scripts/run_offline_regressions.py`는 테스트에서 외부 소켓 연결을 차단한다. 가상 AI/메일 응답, 실제 기존 문서 렌더러의 회귀 테스트, Streamlit AppTest를 실행한다. 기존 비공개 ECLADO 카탈로그 seed가 필요한 테스트는 검증된 개인 테스트 환경에서 실행하며 해당 seed를 Git에 추가하지 않는다.

운영에서는 로그인 후 **관리자 모니터링 → 모니터링 연결 점검 → 새로고침**으로 실제 메타데이터 저장을 확인할 수 있다. 연결 점검은 AI/메일/문서 요청을 실행하지 않으며 `monitor.health` 작업만 기록한다. 운영 검증 상태는 아래 결과에 따르며 main 반영만으로 실화면 확인을 완료했다고 보고하지 않는다.

- 독립 브랜치: `feature/master-observability-20261113`
- Supabase: 전용 테이블/서버 전용 권한/30일 TTL/시간별 정리 적용, 트랜잭션을 롤백하는 가상 데이터로 요약/비용/접근 차단 검증 통과.
- 로컬 자동 테스트: `python scripts/run_offline_regressions.py` 전체 851개 통과(계약·무역문서 677개 + Master 174개, 실패/스킵 0). 신규 모니터링 단위·통합·화면 27개 포함. 기존 문서 자산/출력 어댑터 보호 11개도 별도 통과. 독립 코드 검토의 시작 실패/메타데이터 처리/백분위 계산 지적을 RED→GREEN으로 검증해 수정.
- Streamlit: 기존 운영 로그인 화면 확인. 인증 만료로 관리자 화면의 배포 후 실확인은 아직 미확인.
