# 선택 메일 → AI 업무 요청 → 기존 문서 엔진

## 확인된 이전 상태와 변경

이전 메일함의 **이 메일로 AI 업무 요청 작성** 버튼은 본문을 입력창으로 복사할 뿐 추출을 실행하지 않았다. CIPL과 quotation/견적서 표현은 누락됐고, 계약 분석을 무역서류 한 품목으로 바꾸는 경로는 여러 품목과 포장 수치를 전달하지 못했다.

추가한 흐름:

1. 메일함에서 메일을 선택한다. 열람·동기화 자체로는 AI가 실행되지 않는다.
2. 필요하면 **AI에 함께 보낼 첨부파일**에서 원본 PI 등 PDF/이미지를 직접 선택한다.
3. **AI로 거래조건 추출·문서 준비** 버튼으로 표시된 본문·선택 첨부의 AI 처리를 요청한다.
4. **AI 업무 요청**으로 이동하면서 거래조건을 한 번 추출하고 문서 후보를 채운다. 화면 새로고침이나 이전 실패를 이유로 자동 재호출하지 않는다.
5. 문서 선택, 누락 정보 입력, 전체 품목·포장 값과 원문 검토 후 기존 문서 생성 버튼을 사용한다. 기존 **요청 작성** 버튼도 유지하며, 이 경로는 동의·추출 버튼을 따로 누를 수 있다.

PI/proforma invoice/quotation/견적서는 PI, purchase order/발주서는 PO, contract/agreement/계약서는 CONTRACT, CIPL/CI/PL은 CI와 PL 각각으로 연결한다. 이전 인용문은 새 문서 종류를 결정하지 않지만 거래 근거를 잃지 않도록 전체 본문은 유지한다. 명시적인 새 요청과 부정 표현을 우선한다. 탐지는 검토 가능한 후보이며 UI에서 종류를 수정할 수 있다.

## 보존한 규칙

- 원본 메일·서버 읽음 상태를 수정하거나 자동 발송하지 않는다. 계약 체결·서명·최종 발행도 자동 승인하지 않는다.
- 기존 무역서류 추출기와 계약 분석기를 재사용한다. 여러 품목과 단가 기준·통화·수량 0·포장 수치를 보존한다. PO와 판매 문서는 별도 추출하므로 구매/판매 당사자와 가격을 합치지 않는다.
- 실제 API 스키마의 nullable paid/free/shipped 수량은 기존 수량 규칙으로 처리하며 명시적 모순은 검증에 남긴다. 사용자가 수량을 고치면 실제 금액에 사용되는 paid_quantity와 출하 수량도 함께 갱신한다.
- 배송지는 명시적인 Ship To 등 근거가 있어야 하며 Buyer 주소나 EXW 창고에서 추측하지 않는다.
- 사람의 입력으로 해결된 정확한 누락 항목만 해제한다. 불명확한 기타 항목·충돌·원본 PI 요구를 일괄 삭제하지 않는다.
- CI 출력은 원본 PI 첨부 경로와 거래가격 검증을 유지한다. 메일 본문 가격만으로 원본 PI가 있는 것처럼 승인하지 않는다. CI 출력 어댑터에도 누락됐던 기존 source-PI 검사를 연결했다.
- 원본 PI/이미지 추출의 시각 대조 경고, CIPL 합계 검토·승인, 카탈로그 가격 확인과 직인·은행정보 검증은 남는다. 첨부만 있어도 최종 발행 가능하다는 뜻은 아니다.
- 회사 직인·로고·공유 PDF/XLSX 렌더러와 계약 서식은 수정하지 않는다. 저장된 계약서나 다른 메일, 선택하지 않은 첨부는 보내지 않는다. 새 기능은 본문이나 개인정보를 실행 로그에 추가하지 않는다.
- 메일 요청 12,000자 제한, 첨부 최대 5개/파일당 10MB/합계 20MB를 기존 검증으로 제한한다. 긴 원문은 자동 절단하지 않고 편집을 요청한다.

## 테스트 자료와 검증 범위

`orchestration/tests/mail_fixtures.py`는 실제 고객정보가 없는 **160개 가상 메일**을 재현 가능하게 생성한다. 16종 요청 표현, PI/PO/CI/PL/계약 및 복합 요청, 한국어·영어, USD/EUR/KRW/CNY, PCS/KG, 1~2품목, 수량 0, 소수 단가, Incoterms와 포장 데이터를 포함한다. MIME 메일 파싱 → 요청 인식 → 실제 추출기 HTTP 경계 → 원문 근거 검증 → 문서별 후보 → 기존 금액 검증을 통과시킨다.

외부 AI 응답은 독립된 정답 데이터의 **가상 HTTP 응답**으로 공급한다. 실제 모델 정확도 100%나 실제 메일함 160건 발송·수신을 검증했다고 주장하지 않는다. 별도 정책 테스트는 인용/부정/긴 메일/무동의/가짜 승인/원본 PI/배송지/미완료 계약/수량 수정/누락 보완을 확인한다. Streamlit AppTest는 한 번 클릭한 이동·추출, 중복 방지, 실패, 모델 설정 누락, 문서 변경 시 파일 무효화, 수량 수정 후 실제 금액을 확인한다.

최종 검증: `python scripts/run_offline_regressions.py` 전체 **1,030개 통과**(계약/문서 678개 + Master 352개), 실패/스킵 0. 160개 가상 메일 + 정책 12개 + Streamlit 6개 테스트와 원본 PI 보호 테스트가 포함된다. 독립 리뷰 지적은 각각 실패 테스트로 재현 후 수정했다. 운영 실화면은 이전 작업에서 Google 외부 인증이 자동 승인 검토에 의해 차단됐으므로 아직 미확인이다. 인증을 우회하지 않는다.
