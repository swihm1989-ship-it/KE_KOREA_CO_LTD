# 문서별 작업 유지 및 백그라운드 실행

목표: PI/PO/CI/PL/CIPL과 준비 중 메뉴 사이를 이동해도 주문 입력, 첨부, 검토값, 승인, 다운로드를 보존하고 진행 중 추출·생성을 계속한다. 같은 브라우저 세션 내 유지이며 서버 재시작/브라우저 새 세션의 영구 보관은 범위 밖이다.

설계: 기존 계산·검증·렌더러는 유지한다. 세션별 작업 관리자가 문서 메뉴별 상태와 제한된 백그라운드 실행기를 소유한다. 작업 스레드는 Streamlit에 접근하지 않고 입력 복사본으로 실행하며, 메인 화면이 완료 결과를 원래 메뉴에 반영한다. 각 생성은 고유 출력 디렉터리를 사용한다. 이미 편집된 문서의 오래된 생성 결과는 다운로드에 반영하지 않는다. 자동 상태 확인은 Streamlit fragment로 수행한다. 동일 메뉴의 동일 종류 작업은 중복 실행하지 않는다.

상태 저장만 추가하면 진행 중 API 요청이 메뉴 이동에 중단될 수 있다. 외부 작업 큐는 현재 앱에 추가 운영 인프라가 필요하므로, 사용자가 허용한 비동기를 기존 프로세스 내 제한된 스레드로 구현한다.

- [x] 실패 테스트: 문서별 입력·다운로드·업로드 분리, PI/PO 동시 작업, 완료 결과 소속, 오래된 생성 결과 차단, 실패 후 재시도, 중복 요청 방지, 준비 중 메뉴 왕복.
- [x] 독립 모듈 `agent/workflow_state.py`에 메뉴 상태/작업 관리자 구현.

- [x] 화면 회귀 테스트로 다섯 메뉴 왕복과 진행 중 이동을 확인하고 전체 테스트 및 diff 검사 실행.
