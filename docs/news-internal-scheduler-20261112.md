# News refresh recovery for all categories

All four categories had the same 11:00 KST collection timestamp while GitHub's scheduled run never appeared. Materials and macro also used narrow English searches in the Korean edition. Both now include Korean terms and Korean/US editions. The app's database cache expires after five minutes instead of thirty.

Supabase now queues 11 fixed public RSS URLs at minutes 07 and 37 with pg_cron + pg_net. An independent minute worker ingests completed responses; it does not refetch feeds every minute. A 20-minute enqueue guard avoids overlapping dispatches. Private source/request tables have no client grants, RLS and no policies, so client access is denied. Scheduler functions use invoker privileges and are not executable by public/anon/authenticated. No secrets or external paid server were added. Metadata only; HTTPS links and last-24-hour publication dates are required; DTD/entity declarations and feeds over 1 MB are rejected. Failed feeds retain previous stored articles. Request results remain for seven days; existing 24-hour article cleanup is preserved. GitHub remains a backup collector.

Deployment SQL: supabase/news_scheduler.sql. Parser regression: supabase/tests/news_scheduler.sql. Security advisor: pg_net's default extension namespace is public and is non-relocatable; its HTTP objects live in net with extension-managed default privileges. Attempts to revoke those defaults as postgres do not change supabase_admin-owned ACLs; no restriction of those extension defaults is claimed. No new public application RPC is exposed. RLS-without-policy notices are intentional deny-by-default for these server-only tables. Existing README files are unchanged under the owner's documentation-sync exception for this MASTER work.
